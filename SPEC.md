# Build Prompt: "Daily Read" — 30-Minute Book Summary Platform (CLI-powered Web App)

Copy everything below the line into your AI coding agent.

---

## Role & Goal
You are a senior full-stack engineer and product designer. Build a **local-first web app, controlled from the command line**, that gives me **one 30-minute readable book summary every day** from a curated list of the world's best books across every major area of learning and growth. It must **notify me every day at a time I choose**.

## Tech Stack (keep it simple, no heavy frameworks)
- **Runtime:** Node.js (LTS), launched via a global CLI command `dailyread`.
- **Server:** Node built-in `http` module (or a tiny Express server) serving a local web UI at `http://localhost:4747`.
- **Frontend:** Vanilla HTML + CSS + JavaScript. Google Fonts (e.g., *Inter* for UI, *Lora* or *Literata* for reading text).
- **Storage:** Local JSON files (or SQLite via `better-sqlite3`) in `./data/` — books catalog, settings, reading history, cached summaries.
- **AI summaries:** Generated by an LLM. Support two providers via config:
  1. API key (Gemini / OpenAI / Anthropic) in a `.env` file, **or**
  2. A configurable shell command (e.g., `gemini -p "{prompt}"`) so any installed AI CLI can be used.
- **Notifications (must work even if the browser is closed):**
  - Windows: native toast notification (via `node-notifier` or PowerShell `BurntToast`), registered with **Windows Task Scheduler** so it fires daily even if the app isn't running.
  - macOS/Linux fallback: `node-notifier` + `cron`/`launchd`.
  - In-browser: Notification API + service worker when the tab is open.
  - Clicking the notification opens today's summary in the browser.

## CLI Commands
```
dailyread start                 # start local server + open browser
dailyread stop                  # stop server
dailyread today                 # open (or print in terminal) today's summary
dailyread today --terminal      # read the summary right in the terminal (paged, formatted)
dailyread set-time 07:30        # set daily notification time (re-registers scheduled task)
dailyread next                  # skip today's book, get the next one
dailyread pick "Book Title"     # choose a specific book for today
dailyread generate --days 7     # pre-generate the next 7 summaries (cache, offline reading)
dailyread categories            # list categories + enable/disable/weight them
dailyread history               # show books read, streak, completion stats
dailyread add "Title" --author "Name" --category "Finance"   # add my own book
dailyread export --format md|pdf  # export a summary
dailyread doctor                # check config, API key, scheduler, notifications
```

## Daily Book Selection Logic
- A **365-day rotating curriculum**: never repeat a category two days in a row; balance non-fiction/fiction (~70/30, configurable).
- Respect per-category weights I set (e.g., more Finance, less Poetry).
- Never repeat a book until the whole catalog is completed (unless I ask).
- Pick the next book at midnight; pre-generate the summary in the background so it's instant when the notification fires.

## The 30-Minute Summary Format (≈6,000–7,000 words at ~230 wpm)
Each summary must be **original writing** (not copied text from the book) and follow this structure:
1. **Header:** title, author, year, category, est. reading time, 1-line "why this book matters."
2. **The Big Idea** (≈150 words) — the core thesis in plain language.
3. **About the Author & Context** (≈300 words).
4. **Chapter-by-Chapter / Part-by-Part Breakdown** (≈3,500 words) — key arguments, stories, examples.
   - *For fiction:* plot arc (spoiler warning toggle), characters, themes, symbolism, writing style, why it's a classic.
5. **10 Key Ideas / Lessons** with a real-life example for each (≈1,200 words).
6. **Memorable Quotes** (3–5 short, attributed quotes).
7. **Criticisms & Counterpoints** (≈300 words) — balanced view.
8. **Apply It Today** — 3–5 concrete actions or reflection prompts.
9. **If You Liked This, Read Next** — 3 related books from the catalog.
10. **5-Question Quick Quiz** (with reveal answers) to lock in learning.

## Web UI Requirements (premium, beautiful)
- **Dark mode by default** with a warm light "paper" mode toggle; glassmorphism cards; smooth gradients; subtle micro-animations.
- **Today page:** big book card (AI-generated or Open Library cover via `https://covers.openlibrary.org`), category chip, reading-time ring, "Start Reading" button.
- **Reader view:** distraction-free, adjustable font size/line height, reading progress bar, time-remaining estimate, auto-saved scroll position, highlight & note-taking, "Mark as finished."
- **Library:** browse all books by category, search, filter by read/unread, queue books.
- **Stats:** streak counter, books finished, minutes read, category radar chart ("growth wheel").
- **Settings:** notification time, timezone, days of week, categories & weights, fiction ratio, AI provider, summary length (15/30/45 min).
- Optional: text-to-speech "listen mode" using the Web Speech API.
- SEO basics, semantic HTML, unique IDs on all interactive elements, fully responsive.

## Acceptance Criteria
- `npm install -g .` then `dailyread start` opens the app with today's book ready.
- `dailyread set-time 08:00` → a native notification appears at 08:00 tomorrow even if the app/browser is closed; clicking it opens the summary.
- Summaries are $\ge 60$ min / 1 hour ($\ge 13,800–14,000$ words), follow the masterclass multi-section breakdown, and are cached for offline reading.
- Streaks, history and highlights persist across restarts.
- `dailyread doctor` reports all green on a fresh install.
- README with setup steps, screenshots, and how to add API keys.
